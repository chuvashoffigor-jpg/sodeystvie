# Сайт «Содействие» — статическая версия

Это ваш сайт, перенесённый из Tilda в обычный код (HTML/CSS/JS), без зависимости
от Tilda и её подписки. Визуал, анимации, переключение RU/EN и вся логика
сохранены как есть — просто теперь это набор файлов, который можно положить
в GitHub и задеплоить на Vercel.

Внешних зависимостей у сайта две: шрифт Google Fonts (Golos Text) и одна
картинка логотипа (см. пункт «Логотип» ниже). Больше сайт ни от чего не зависит.

## Структура проекта

```
├── index.html              Главная            → /
├── uslugi/index.html       Услуги             → /uslugi/
├── o-kompanii/index.html   О компании         → /o-kompanii/
├── news/index.html         Новости            → /news/
├── partners/index.html     Партнёры           → /partners/
├── contacts/index.html     Контакты           → /contacts/
├── forms/index.html        Форма заявки       → /forms/
├── politic/index.html      Политика конф-ти   → /politic/
├── 404.html                 Страница «не найдено»
├── robots.txt / sitemap.xml
└── assets/
    ├── favicon.svg
    └── img/                 сюда нужно положить logo.png (см. ниже)
```

Каждая страница — это папка с `index.html` внутри, поэтому адреса получаются
такими же «чистыми», как были на Tilda (`/uslugi/`, `/contacts/` и т.д.) — это
работает на Vercel и GitHub Pages без дополнительных настроек и редиректов.

Каждая HTML-страница полностью самодостаточна: свой `<style>` и свой `<script>`
внутри файла. Это специально не стал разносить по отдельным .css/.js файлам —
так меньше риск что-то сломать при переносе, и один файл = одна страница, что
удобно, если вы (или другой человек) будете точечно править конкретную
страницу в будущем.

## 1. Посмотреть локально

Файлы обычные, сервер не нужен — можно просто открыть `index.html` в браузере
двойным кликом. Если хотите, чтобы относительные пути и формы вели себя точно
как в проде, поднимите локальный сервер в папке проекта:

```bash
npx serve .
# или
python3 -m http.server 8000
```

## 2. Логотип (обязательно перед публикацией)

Логотип раньше подгружался с CDN Тильды через JS — сейчас код везде ссылается
на `/assets/img/logo.png`, но самого файла в архиве нет: у меня не было доступа
скачать его с `static.tildacdn.com`. Подробная инструкция и обе исходные ссылки
(в коде на Главной и на остальных страницах использовались разные файлы —
стоит проверить, какой актуальный) лежат в
`assets/img/ПОЛОЖИТЕ_ЛОГОТИП_СЮДА.txt`. Кратко: откройте ссылку в браузере,
сохраните картинку как `logo.png` в `assets/img/`.

## 4. Задеплоить на Vercel

1. Зайдите на vercel.com → **Add New → Project**.
2. Выберите только что созданный репозиторий на GitHub.
3. Framework Preset — **Other** (это статический сайт, сборка не нужна).
   Build Command и Output Directory можно оставить пустыми.
4. **Deploy** — через минуту сайт будет доступен на `*.vercel.app`.
5. Если есть свой домен — добавьте его в Project → Settings → Domains.

После того как узнаете финальный домен, замените плейсхолдер
`YOUR-DOMAIN.example` на настоящий домен — он используется в
`<link rel="canonical">` и og-тегах на каждой странице, а также в
`robots.txt` и `sitemap.xml`. Проще всего одной командой:

```bash
grep -rl "YOUR-DOMAIN.example" . | xargs sed -i 's/YOUR-DOMAIN.example/ваш-домен.ru/g'
```

## 5. Формы (важно!)

На Tilda формы «Оставить заявку» и «Подписаться» отправлялись самой платформой
(письмо/CRM). Сейчас в коде это отмечено явно — при отправке форма просто
показывает «Спасибо» на кнопке, но **никуда ничего не отправляет**. Это нужно
починить перед тем, как давать ссылку на сайт клиентам.

Самый быстрый вариант — сервис вроде Formspree или Getform: регистрируетесь,
получаете URL вида `https://formspree.io/f/xxxxxxx`, и в каждой странице,
где есть `<form id="cpa-contact-form" ...>` или `<form id="cpa-subscribe-form" ...>`
(страницы `forms`, `contacts`, а также блок подписки на Главной), добавляете:

```html
<form id="cpa-contact-form" action="https://formspree.io/f/xxxxxxx" method="POST" ...>
```

Существующий JS-обработчик формы делает `e.preventDefault()`, поэтому реальную
отправку нужно либо убрать оттуда, либо заменить на `fetch()` к этому URL —
могу сделать это сразу, если скажете, каким сервисом хотите пользоваться.
